# 04 - 宝塔部署指南

> 前提：本地开发联调已完成（见 `03-现状梳理与验证指南.md`）。
> 部署物只有一个 Linux 单二进制 + 一份 config.yaml；nginx 只做反代，网关不对外监听。

---

## 1. 部署架构

```
用户浏览器
   │  http://你的域名 或 服务器IP
   ▼
宝塔 nginx（:80）  ──X-Forwarded-For 传递真实客户端 IP──▶  ip-gateway（:8080，仅本机监听）
                                                            │ 内存规则匹配 → 302
                                                            ▼
                                                  Redis（可选，规则主源）/ config.yaml（兜底）
```

仓库根目录另有 `docker-compose.yml`（网关 `:18080` + Redis），适合本机或私有化试跑，步骤见 README「Docker」。宝塔生产仍按下文二进制 + nginx，线上 `listen` 用 `:8080`。

---

## 2. 第一步：本地编译 Linux 二进制

先在服务器上确认架构（宝塔机器绝大多数是 x86_64）：

```bash
# 在服务器执行
uname -m    # x86_64 → 用 amd64；aarch64 → 用 arm64
```

在本地项目目录编译（Mac 交叉编译）：

```bash
# x86_64 服务器（最常见）
CGO_ENABLED=0 GOOS=linux GOARCH=amd64 go build -o ip-gateway .

# aarch64 服务器
CGO_ENABLED=0 GOOS=linux GOARCH=arm64 go build -o ip-gateway .
```

> PATH 问题：本机 go 不在默认 PATH，执行前 `export PATH="/usr/local/go/bin:$PATH"`。

---

## 3. 第二步：上传文件并准备线上配置

1. 宝塔 → 文件 → 新建目录 `/www/ipgateway`
2. 上传两个文件：`ip-gateway`（二进制）和 `config.yaml`
3. 终端执行：

```bash
chmod +x /www/ipgateway/ip-gateway
cd /www/ipgateway && ./ip-gateway -config config.yaml   # 手动试跑一次，确认能起
```

**线上 config.yaml 必改的三处**（本地联调配置不能原样照搬）：

| 字段 | 线上值 | 说明 |
|---|---|---|
| `listen` | `":8080"` | 只监听本机给 nginx 反代，**不要对公网开放** |
| `redis.addr` | 服务器 Redis 地址；不装 Redis 就留空 `""` | 留空 = 纯文件模式，改规则靠改 yaml + reload |
| `trusted_proxies` | 保留 `127.0.0.1`（必须） | 没有它网关拿到的是 nginx 的 IP，分流全错 |

`default_target` 和 `rules` 按线上业务填。规则数据可以直接用本地管理后台导出的 JSON（Redis 格式）或本地 config.yaml 里的规则段。

Redis 安装（可选）：宝塔 → 软件商店 → 搜索 Redis → 安装，默认 `127.0.0.1:6379` 无密码。

---

## 4. 第三步：进程守护（二选一）

### 方式 A：宝塔「进程守护管理器」（推荐，面板操作）

1. 宝塔 → 软件商店 → 搜索「进程守护管理器」→ 安装
2. 添加守护进程：

| 项 | 值 |
|---|---|
| 名称 | ipgateway |
| 启动用户 | root |
| 运行目录 | /www/ipgateway |
| 启动命令 | /www/ipgateway/ip-gateway -config /www/ipgateway/config.yaml |
| 进程数量 | 1 |

3. 启动后状态变绿即可；进程崩溃会自动拉起，开机自启。

### 方式 B：systemd

```bash
cp deploy/ip-gateway.service /etc/systemd/system/   # 单元文件已按 /www/ipgateway 写好
systemctl daemon-reload
systemctl enable --now ip-gateway
systemctl status ip-gateway
```

---

## 5. 第四步：宝塔站点 + nginx 反向代理

### 方式 A：面板操作（常规做法）

1. 先把域名 A 记录解析到服务器公网 IP
2. 宝塔 → 网站 → 添加站点：域名填 `gw.example.com`，PHP 版本选「纯静态」，不建数据库
3. 站点设置 → 反向代理 → 添加反向代理：
   - 代理名称：ipgateway
   - 目标 URL：`http://127.0.0.1:8080`
   - 发送域名：`$host`
4. **补 header（关键）**：站点设置 → 配置文件，在 `location /`（反代块）里确认有以下行，缺哪行补哪行：

```nginx
proxy_set_header Host              $host;
proxy_set_header X-Real-IP         $remote_addr;
proxy_set_header X-Forwarded-For   $proxy_add_x_forwarded_for;   # ★ 网关靠它拿真实 IP
proxy_set_header X-Forwarded-Proto $scheme;
```

### 方式 B：直接用现成配置文件

完整示例见 [deploy/nginx-ip-gateway.conf](/Users/mac/code/git/golang-ip-gateway/deploy/nginx-ip-gateway.conf)：
复制为 `/www/server/panel/vhost/nginx/ipgateway.conf`（改 `server_name`），然后：

```bash
nginx -t && nginx -s reload
```

### HTTPS（可选）

站点设置 → SSL → Let's Encrypt 申请证书 → 开启「强制 HTTPS」。网关本身只管 HTTP，证书在 nginx 层终止即可（`X-Forwarded-Proto` 已在配置里）。

---

## 6. 第五步：放行端口

- 宝塔 → 安全：放行 `80`（用了 HTTPS 再放 `443`）
- 云服务器安全组：同样放行 80/443
- **8080 不要放行**：网关只监听本机，由 nginx 反代对外

---

## 7. 第六步：上线验证清单

```bash
# 服务器本机
curl -s http://127.0.0.1:8080/healthz                                   # 期望 {"status":"ok",...}
curl -s "http://127.0.0.1:8080/admin/test?ip=10.100.0.1"                # 验证规则匹配
```

```bash
# 任意机器走域名（验证 nginx → 网关链路 + 真实 IP）
curl -s -o /dev/null -w "%{http_code} %{redirect_url}\n" http://gw.example.com/anything
curl -s "http://gw.example.com/admin/test?ip=8.8.8.8"
```

浏览器直接访问 `http://gw.example.com/任意路径` → 地址栏 302 到目标域名即成功。

真实分流验证：用几台不同网络环境的设备（手机流量/WiFi）访问域名，应各自落到不同域名；或看网关日志（守护进程管理器里可看输出）确认来源 IP 是公网 IP 而不是 `127.0.0.1`。

## 8. 线上怎么改规则（管理后台只在本地跑）

三种方式，按场景选：

**① 服务器 Redis 直接写（推荐，规则多时）**

```bash
redis-cli -h 127.0.0.1 SET ip_gateway:rules '[
  {"type":"segment","ip_cidr":"10.0.0.0/8","targets":["https://s1.xxx.com","https://s2.xxx.com","https://s3.xxx.com"],"enable":true},
  {"type":"random","ip_cidr":"0.0.0.0/0","targets":["https://r1.xxx.com","https://r2.xxx.com"],"enable":true}
]'
curl -X POST http://127.0.0.1:8080/admin/reload    # 热生效，不重启
```

> 注意匹配顺序：分段类规则放前面，随机兜底（0.0.0.0/0）放最后。

**② 改 config.yaml（没装 Redis 时）**

改 `/www/ipgateway/config.yaml` 的 rules 段，然后 `curl -X POST http://127.0.0.1:8080/admin/reload`。

**③ 本地管理后台直连线上（推荐，需网关为支持 CORS 的版本）**

项目已内置 CORS 支持。在「管理环境」里添加线上地址（如 `https://golang-ip-gateway.98maihua.com`）保存后，顶部下拉切到线上即可直接编辑线上规则，保存即线上热生效。

> 服务器上的网关若是旧版（浏览器连线上会提示连接失败），用项目根目录已编译好的 `ip-gateway-linux-amd64` 上传替换并重启守护即可（或重新编译：`CGO_ENABLED=0 GOOS=linux GOARCH=amd64 go build -o ip-gateway .`）。

**④ SSH 隧道（无 CORS 老版本的兼容方案）**

```bash
# 本地执行：把服务器的 8080 映射到本地 18080
ssh -L 18080:127.0.0.1:8080 root@服务器IP

# 另开终端启动本地管理后台，指向隧道
cd admin-ui && GATEWAY_URL=http://127.0.0.1:18080 npm run dev
# 打开 http://localhost:6183 → 现在页面里改的就是线上规则，保存即线上热生效
```

## 9. 更新版本流程

### 9.0 运维命令速查

```bash
# 判断守护方式（决定用哪套启停命令）
systemctl status ip-gateway --no-pager 2>/dev/null | head -3   # systemd
supervisorctl status 2>/dev/null                               # 宝塔进程守护管理器
ps aux | grep -v grep | grep ip-gateway                        # 手动 nohup

# 停止（三选一；被守护托管时不要用 pkill，会和守护打架）
systemctl stop ip-gateway
supervisorctl stop ipgateway
pkill -f 'ip-gateway -config'          # 仅手动 nohup 方式

# 启动（三选一）
systemctl start ip-gateway
supervisorctl start ipgateway
cd /www/ipgateway && nohup ./ip-gateway -config /www/ipgateway/config.yaml > gateway.log 2>&1 &

# 状态检查（线上监听端口以 healthz 输出为准，本例 18080）
ss -tlnp | grep 18080
curl -s http://127.0.0.1:18080/healthz
curl -s -i -X OPTIONS http://127.0.0.1:18080/admin/rules \
  -H "Origin: http://localhost:6183" -H "Access-Control-Request-Method: POST" | head -5
# ↑ 看到 204 + Access-Control-Allow-Origin: * 说明是支持 CORS 的新版
```

### 9.1 更新步骤

```bash
# 本地：改完代码 → 重新编译（当前版本含 CORS/统计/权重/区域分流，地理库已内嵌无需数据文件）
CGO_ENABLED=0 GOOS=linux GOARCH=amd64 go build -o ip-gateway .
# 二进制约 50MB（含内嵌 IP 地理库），上传覆盖 /www/ipgateway/ip-gateway（先备份旧的），然后：
systemctl restart ip-gateway        # systemd 方式
# 或在宝塔守护进程管理器里点「重启」
# 重启后 curl http://127.0.0.1:18080/healthz 应看到 "geo":true（区域分流可用）
```

规则数据在 Redis/yaml 里，升级不丢。

## 10. 常见问题排查

| 现象 | 原因 | 处理 |
|---|---|---|
| 域名访问 502（秒回） | 网关没起来，或监听端口不是 8080 | 服务器执行 `ss -tlnp \| grep 8080`；多半是把本地 config.yaml（`listen: ":18080"`）直接传上去了，改成 `":8080"` 后重启守护 |
| 所有 IP 都跳同一个目标 | nginx 没传真实 IP | 检查 `X-Forwarded-For` header；确认 config.yaml `trusted_proxies` 含 127.0.0.1 |
| 改了 Redis 规则没生效 | 忘了触发 reload | `curl -X POST http://127.0.0.1:8080/admin/reload`（网关不主动轮询） |
| 日志一直报 redis 连接失败 | Redis 没装/密码不对 | 装了 Redis 就改 `redis.addr`；不用 Redis 就把 `addr` 留空，走文件模式（功能完整） |
| reload 后规则没变 | Redis 里是旧规则，reload 优先读 Redis | 更新 Redis 后再 reload；或临时清空 redis key 让它走文件 |
| 服务器是 arm 报「cannot execute binary」 | 编译架构不对 | `uname -m` 确认后用 GOARCH=arm64 重新编译 |
