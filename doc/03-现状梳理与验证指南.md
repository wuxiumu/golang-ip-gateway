### 1.2 两分类模式的行为定义（2026-10-07 按用户心智模型重做）

| 分类 | 你要做的 | 系统自动做的 | 关键特性 |
|---|---|---|---|
| 分类1 · 随机分配 | 只添加域名 | 所有来访 IP 按哈希自动分配到某个域名 | 同一 IP 永远固定同一个域名；纯哈希不落库，重启/重载不变；域名顺序变化会重新洗牌 |
| 分类2 · IP 分段 | 填一段 IP + 按顺序添加域名 | 把网段平均切分成与域名数相同的段，实时预览每段 IP 范围 | 第 1 段 → 第 1 个域名，末段含余数；段边界已用脚本验证 |

> 底层引擎还保留 basic（单域名固定）类型，供 Redis/文件直接配置时兼容使用，管理后台不再展示。

## 2. 使用流程（两个分类，各一个配置）

0. **先选环境**：页面顶部的环境下拉可切换「本地 / 线上」等网关，绿点 = 连接正常（healthz 探测）；「管理环境」里可增删改地址（存在浏览器 localStorage，可直接粘贴带 `/healthz` 的地址）。之后所有读取、保存、测试都作用于当前选中环境。
1. 页面只有两个分类标签：
   - **分类1 · 随机分配**：只管添加域名。所有来访 IP 自动被哈希分配到其中一个域名，同一个 IP 永远固定同一个域名（不落库，重启不变）。
   - **分类2 · IP 分段**：选**分几段**（1~50）→ 系统自动生成默认域名配置并填好 IP 段默认值；把默认域名改成你的即可。系统把网段**平均切分**成相同段数，页面实时显示每段 IP 范围预览；第 1 段 → 第 1 个域名。
2. 每个分类下方自带「测试」：输入 IP（不填用默认）→「查看分配结果」看该 IP 固定到哪个域名；「浏览器打开真实跳转」直接 302 看落点。
3. 点「**保存并热生效**」：两个分类一起保存，规则立即生效、回写 yaml、尽力写 Redis，不用重启。
4. 两个分类都不填域名并保存 = 关闭该分类。

> 匹配顺序：IP 分段在前，随机分配兜底（其余所有 IP）。默认跳转目标只对无法解析的来源 IP 生效。

## 3. 默认参考测试数据（当前线上配置即此套）

| 分类 | 配置 | 测试 IP | 预期跳转 |
|---|---|---|---|
| 分类2 · IP 分段 | `10.0.0.0/8` → s1/s2/s3（自动三等分） | `10.0.0.1` | s1（第 1 段） |
| 分类2 · IP 分段 | 同上 | `10.100.0.1` | s2（第 2 段） |
| 分类2 · IP 分段 | 同上 | `10.200.0.1` | s3（第 3 段） |
| 分类1 · 随机分配 | 全部 IP → r1/r2/r3（哈希分配） | `8.8.8.8` | r3（该 IP 永远固定 r3） |
| 分类1 · 随机分配 | 同上 | `114.114.114.114` | r1 |
| 分类1 · 随机分配 | 同上 | `223.5.5.5` | r3 |

> 随机分配的期望值由 IP 哈希决定，是**确定性的**：同一套域名列表下，`8.8.8.8` 任何一次重启后都指向 r3，可直接写进自动化断言（验证脚本就是这么做的）。

## 4. 验证脚本与日志

```bash
./scripts/verify.sh
```

- **隔离执行**：在空闲端口（18099 起）自起一个临时网关实例，加载固定的参考数据，不碰你正在运行的网关、config.yaml 和 Redis 数据（Redis 故意指向不通的端口，顺带验证文件兜底）
- **覆盖范围**：三类规则匹配、段边界、随机粘性与分布、真实 302（整链 + 单规则）、不匹配 400 / 未知规则 404、保存热生效、reload 降级、enable 开关、规则 ID 重启稳定，共 26 项
- **日志**：每次运行生成 `logs/verify-<时间戳>.log`（控制台与日志内容一致，含网关自身日志），末尾汇总 `通过 N 项 / 失败 M 项`；有失败时退出码为 1，方便以后接 CI
- 二进制不存在时会自动编译（优先找 `/usr/local/go/bin/go`）

## 5. 已知边界

- 随机/分段的候选域名**顺序参与计算**：保存后追加域名放最后，调整顺序会改变已有 IP 的分配关系
- `*.example.com` 是示例域名，浏览器跳转测试时会 DNS 打不开，属正常——地址栏落点即跳转地址；换真实域名即可完整打开
- 预留字段（weight/ua_contains/path_prefix/country）在 UI 上不展示、不参与匹配
