## 1. 项目定位

一句话：一个 Go 实现的 HTTP 流量入口网关，根据客户端 IP 命中规则后返回 **302 跳转**到指定目标域名，未命中走默认域名。

- 定位：轻量分流/跳转层，**不做代理转发**（不回源取内容），只做 302。
- 配置存储：Redis（主）+ 本地 yaml（兜底），**不引入 MySQL**。
- 管理后台：React 实现的本地管理页面，**只在本机运行（开发模式），不部署到服务器**，通过网关 Admin API 管理规则。
- 部署形态：Go 网关单二进制，部署到**宝塔面板服务器**。

## 2. 核心功能需求

| 编号 | 需求 | 说明 |
|---|---|---|
| FR-1 | HTTP 入口与 302 跳转 | 所有非管理路径的请求统一进入分流逻辑，命中规则返回 302 到目标域名 |
| FR-2 | IP / IP 段匹配 | 规则以 IP 或 CIDR 网段表达（支持 `1.2.3.4` 单 IP 和 `192.168.1.0/24` 网段），按序匹配，第一条命中即返回 |
| FR-3 | 默认跳转 | 未命中任何规则（或来源 IP 无法解析）时，302 到 `default_target` |
| FR-4 | 规则开关 | 每条规则有 `enable` 开关，关闭的规则直接跳过 |
| FR-5 | 双配置源 + 自动降级 | Redis 为主配置源；启动或刷新时 Redis 不可用，自动降级读本地 `config.yaml`，服务不中断、不崩溃 |
| FR-6 | 规则内存常驻 | 业务请求路径**完全不访问 Redis / 磁盘**，只读内存；配置加载阶段预编译 CIDR |
| FR-7 | 热刷新管理接口 | 提供 `/admin/reload`，触发后重载规则到内存，**无需重启进程**；Redis 异常时自动回退本地文件；刷新失败保留旧配置。鉴权可选：`admin_token` 留空则不鉴权（本期决策） |
| FR-8 | 规则备注 | 每条规则支持 `remark` 备注，便于维护 |
| FR-9 | React 管理后台（本地） | 本地 React 页面：两分类规则定制、保存后热生效、触发重载、查看当前规则来源（redis/file/admin）。仅本地运行。**支持多环境切换**（本地/线上等），环境列表与当前选中保存在浏览器 localStorage，可增删改；接口地址可直接粘贴带 `/healthz` 的完整地址（自动规整）；顶部实时显示连接状态（healthz） |
| FR-10 | IP 匹配测试接口 | `GET /admin/test?ip=x.x.x.x` 返回该 IP 命中的规则与目标域名，便于上线前验证规则正确性 |
| FR-11 | 管理接口双写持久化 | 管理后台保存规则时：本地 yaml **必写**（保证兜底一致），Redis **尽力写**（失败不影响保存与热生效） |
| FR-12 | 规则分类（两分类模式） | 管理后台只暴露两个分类：**随机分配**——只添加域名，系统自动把每个来访 IP 哈希分配到其中一个域名，同一 IP 永久固定（不落库、重启不变）；**IP 分段**——填一段 IP + 按顺序添加域名，系统自动把网段均分成与域名数相同的段，第 N 段 → 第 N 个域名（末段含余数）。IP 分段规则排在随机分配之前匹配；底层仍兼容 basic 单域名规则（Redis/文件直接配置时可用） |
| FR-13 | 浏览器真实跳转测试 | 管理后台按分类 tab 组织规则；每条规则可填一个测试 IP，生成 `?ip=` 形式的测试 URL（`/admin/go`），浏览器打开即执行**真实 302 跳转**，直观看到落到的域名；支持整链测试与单规则测试 |

**职责边界**：Redis 只存规则数组（JSON）；`listen`、`default_target`、`admin_token`、Redis 连接、信任代理等全局参数以本地配置文件为准。

## 3. MVP 范围

### 3.1 本期实现（MVP）

- IP/CIDR → target 单一映射，`enable` 开关，`default_target` 兜底
- 规则分类三种：基础固定 / 随机固定（IP 哈希、无需存储）/ 分段固定（网段均分）
- Redis 规则（JSON 数组，key 如 `ip_gateway:rules`）+ 本地 yaml 兜底，自动降级
- Admin API：规则读写、热刷新、IP 测试、健康检查（`/healthz`）
- React 本地管理后台（Vite 开发模式 + API 代理）
- 宝塔服务器部署（单二进制 + 进程守护 + nginx 反代真实 IP）
- 基础日志：启动、规则加载来源（redis/file）、刷新结果、降级事件

### 3.2 本期不做，仅预留字段（后续版本）

- UA 匹配、path 前缀匹配、国家/地域匹配（maxmind）
- 权重分流、多目标随机、灰度、时间窗口、黑白名单
- 定时自动刷新（网关默认不轮询 Redis，由管理侧触发 reload）
- 管理后台部署到服务器、后台权限体系

> Rule 结构体层面预留 `weight / ua_contains / path_prefix / country / remark` 字段，保证后续扩展不改动主流程。

## 4. 非功能需求

| 编号 | 类别 | 要求 |
|---|---|---|
| NFR-1 | 性能 | 请求路径零 IO、锁开销最小化；2核2G 充分利用多核；支撑高并发跳转 |
| NFR-2 | 可用性 | Redis 宕机不影响线上跳转流量（内存规则继续生效）；刷新失败保留旧配置，无空窗期 |
| NFR-3 | 安全 | **本期明确不作为重点**（用户决策）。`admin_token` 可配置，留空不鉴权；管理后台仅本地运行，天然不暴露公网 |
| NFR-4 | 部署 | `CGO_ENABLED=0` 编译 Linux 单二进制；宝塔面板进程守护（开机自启、崩溃自动拉起）；nginx 反代并传递真实客户端 IP |
| NFR-5 | 可维护性 | 配置变更不重启服务；管理后台或写 Redis + 调 reload 即可生效 |

## 5. 关键流程（需求视角）

### 5.1 启动流程

1. 读本地 `config.yaml` → 写入内存（保证一定有可用配置）
2. 尝试读 Redis 规则 → 成功则整体替换内存规则；失败保留 yaml 配置，**正常启动不崩溃**
3. 监听端口，对外服务

### 5.2 请求处理

1. 取真实客户端 IP → 内存中按序匹配启用的 CIDR 规则
2. 命中 → 302 到该规则 target；未命中 / IP 无效 → 302 到 `default_target`
3. 全程不触 Redis、不读磁盘

### 5.3 规则更新（线上变更）

1. 管理侧把规则 JSON 数组写入 Redis key
2. 调用 `/admin/reload`
3. 网关重载内存；Redis 失败自动回退加载本地 yaml；两者都失败则保留旧配置并报错

### 5.4 管理后台操作流程（本地）

1. 本地启动网关与 React 开发服务（Vite 代理 Admin API）
2. 页面上编辑规则 / 默认目标 → 点保存 → 网关内存热生效 + 回写 yaml + 尽力写 Redis
3. 用页面内置「IP 测试」验证命中结果，再发布到线上

## 6. MVP 验收清单（可验证）

### 启动与加载

- [ ] 无 Redis 时程序可启动，使用 yaml 规则正常跳转
- [ ] Redis 有规则时启动，加载 Redis 规则（日志体现配置来源）
- [ ] `config.yaml` 缺失或格式非法时启动失败并给出明确报错

### 分流正确性

- [ ] 命中单 IP / CIDR 网段 → 302 到对应 target
- [ ] 未命中 → 302 到 `default_target`
- [ ] `enable=false` 的规则被跳过
- [ ] 来源 IP 无法解析 → `default_target`
- [ ] `/admin/test` 返回的命中结果与实际跳转一致
- [ ] 随机固定：同一 IP 多次测试命中同一域名；不同 IP 能分布到不同候选域名；重启后分配不变
- [ ] 分段固定：段边界两侧的 IP 分别命中前后两个域名；末段包含除不尽的余数
- [ ] `/admin/go?ip=` 浏览器打开返回真实 302，地址栏落到目标域名
- [ ] `/admin/go?rule=&ip=` 单规则测试：命中该规则时 302 到规则算出的目标；IP 不属于该规则时返回 400 说明
- [ ] 规则 ID 重启后保持不变，旧测试链接继续可用

### 热刷新与管理后台

- [ ] 管理后台保存规则后，无需重启即生效
- [ ] 保存时 yaml 回写成功；Redis 不可用时报错提示但保存与热生效不受影响
- [ ] `/admin/reload`：Redis 优先，停机后自动回退 yaml
- [ ] （仅当配置 `admin_token` 时）错误 token → 403
- [ ] 刷新过程中旧规则持续可用（无空窗）

### 部署

- [ ] Linux 单二进制在宝塔服务器由进程守护运行、崩溃自动重启
- [ ] 经宝塔 nginx 反代访问时按真实客户端 IP 分流（而非 127.0.0.1）

## 7. 已确认决策（2026-10-07）

1. **安全**：本期不考虑安全问题，admin 接口鉴权可选（token 留空即不启用）。
2. **管理后台**：React 实现，仅本地运行（Vite dev），不部署服务器。
3. **部署**：Go 本地开发编译，上线部署到宝塔服务器（进程守护 + nginx 反代）。
4. **Redis 连接信息**：放入 config.yaml（不再硬编码）。
5. **匹配顺序**：规则数组顺序，第一条命中即返回；单 IP 等价于 /32 网段。
6. **跳转语义**：302 临时跳转。
7. **健康检查**：提供 `/healthz`（顺带满足探活需求）。
