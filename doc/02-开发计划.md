## 3. Admin API 设计

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/healthz` | 健康检查：规则数、当前配置来源、监听地址 |
| GET | `/admin/rules` | 读取当前内存配置（rules + default_target + source） |
| POST | `/admin/rules` | 保存规则并热生效：内存替换 + 回写 yaml（必写）+ 写 Redis（尽力）；请求体 `{"default_target":"...","rules":[...]}` |
| POST | `/admin/reload` | 重载配置：Redis 优先，失败回退 yaml，都失败保留旧配置 |
| GET | `/admin/test?ip=` | 模拟匹配：返回 `{"ip","matched_rule"(下标,-1 未命中),"target","detail"}` |
| GET | `/admin/go?ip=&rule=` | **真实 302 跳转测试**（浏览器打开直接看到跳到哪个域名）：只传 `ip` 按完整规则链匹配；传 `rule=<规则ID>` 只测指定规则，IP 不匹配该规则返回 400 说明，ID 不存在返回 404。规则 ID 由内容哈希生成（`/admin/rules` 返回的 `id` 字段），保存后持久化、重启不变 |

- 鉴权：`admin_token` 非空时要求请求头 `X-Admin-Token` 匹配；留空则不鉴权（本期决策）。
- Redis 中存储格式：`SET ip_gateway:rules` → 规则数组的 JSON（与 plan.md 一致）。

### 规则分类与数据结构（FR-12）

每条规则有 `type` 字段（空视为 `basic`），选中哪类就按哪类逻辑匹配：

| type | 名称 | 逻辑 |
|---|---|---|
| `basic` | 基础 | 命中 `ip_cidr` → 302 到 `target`（单域名） |
| `random` | 随机固定 | 命中 `ip_cidr` 后，对 IP 做哈希（FNV-1a，盐为该规则的 ip_cidr）从 `targets` 中选一个；**同一 IP 永远固定同一个域名**，纯计算不落库，重启/重载不变；候选顺序变化会重新洗牌 |
| `segment` | 分段固定 | 把 `ip_cidr` 网段按 `targets` 数量**均分**，第 1 段 → 第 1 个域名，依此类推；末段包含除不尽的余数 |

数据结构（Redis JSON 与 yaml 同构，管理后台直接编辑）：

```json
[
  {"type":"basic","ip_cidr":"192.168.1.0/24","target":"https://a.example.com","enable":true,"remark":"内网A组"},
  {"type":"random","ip_cidr":"0.0.0.0/0","targets":["https://r1.example.com","https://r2.example.com","https://r3.example.com"],"enable":true,"remark":"全量IP随机固定"},
  {"type":"segment","ip_cidr":"10.0.0.0/8","targets":["https://s1.example.com","https://s2.example.com"],"enable":true,"remark":"B段对半分"}
]
```

保存校验：`basic` 必填 `target`；`random`/`segment` 必填至少 1 个非空 `targets`；`ip_cidr` 必须合法（单 IP 或 CIDR）。

### config.yaml 字段

| 字段 | 说明 |
|---|---|
| `listen` | 监听地址；本地联调 `:18080`（本机 8080 被其他服务占用），服务器上可用 `:8080` |
| `default_target` | 未命中规则时的 302 目标（必填） |
| `admin_token` | 管理接口 token，留空不鉴权 |
| `trusted_proxies` | 信任的反代列表；宝塔 nginx 在本机需含 `127.0.0.1`，否则拿到的是代理 IP 导致分流错乱 |
| `redis.addr/password/db/key` | Redis 连接与规则 key；`addr` 留空 = 纯文件模式 |
| `rules[]` | 兜底规则：`type / ip_cidr / target / targets / enable / weight / ua_contains / path_prefix / country / remark`（分类见上节；weight 等后四项本期预留） |

## 5. 本地运行指南

前置：`PATH` 需包含 `/usr/local/go/bin`；npm 用 nvm 的 Node 24（`PATH` 前置 `~/.nvm/versions/node/v24.18.0/bin`，系统自带 node v12 跑不了 Vite）。

本机 8080 / 5173 / 5175 已被其他项目占用，本地默认端口定为：**网关 :18080、管理后台 :6183**（config.yaml 与 vite.config.js 已按此配置，vite 开了 strictPort 防止悄悄跳端口）。

```bash
# 1. 启动网关（终端 1）
cd golang-ip-gateway
go run .                     # 监听 :18080；Redis 本地已在跑则自动加载 redis 规则

# 2. 启动管理后台（终端 2）
cd admin-ui
npm install                  # 仅首次
npm run dev                  # 打开 http://localhost:6183，/admin 自动代理到 :18080

# 3. 验证
curl -s http://127.0.0.1:18080/healthz
curl -s -o /dev/null -w "%{http_code} %{redirect_url}\n" http://127.0.0.1:18080/any-path
curl -s "http://127.0.0.1:18080/admin/test?ip=10.2.3.4"
```

## 6. 宝塔部署指南（P6，上线时执行）

> 完整步骤、nginx 配置、线上改规则与排错见 **[04-宝塔部署指南.md](/Users/mac/code/git/golang-ip-gateway/doc/04-宝塔部署指南.md)**；nginx 配置示例文件：`deploy/nginx-ip-gateway.conf`。核心流程概要：

1. **编译**（本地 Mac 交叉编译，按服务器架构选 GOARCH）：
   ```bash
   CGO_ENABLED=0 GOOS=linux GOARCH=amd64 go build -o ip-gateway .
   ```
2. **上传**：二进制 + `config.yaml` 放到服务器，如 `/www/ipgateway/`（线上 config 记得改 `listen: ":8080"`）。
3. **进程守护**（二选一）：
   - 宝塔软件商店安装「进程守护管理器」，添加守护进程指向 `/www/ipgateway/ip-gateway`（等同 supervisor，崩溃自动拉起）；
   - 或使用 `deploy/ip-gateway.service` 走 systemd。
4. **反代**：宝塔新建站点（域名/IP）→ 反向代理到网关监听端口（服务器上 config.yaml 建议 `listen: ":8080"`，本仓库里的 `:18080` 是本地联调用）；nginx 默认会带 `X-Forwarded-For`，网关侧 `trusted_proxies` 已含 `127.0.0.1`，拿到的是真实客户端 IP。
5. **Redis**（可选）：服务器自装或云 Redis，把地址填入线上 `config.yaml`；不填则纯文件模式运行（改规则靠管理后台保存回写 yaml + 手动 reload）。
6. **验证**：`/healthz` 正常；用真实外网 IP 调 `/admin/test` 核对分流；浏览器访问确认 302。

> 注意：本地管理后台不部署；线上改规则 = 写 Redis（`SET ip_gateway:rules`）+ `POST /admin/reload`，或临时在服务器上改 yaml 后调 reload。

## 7. 与 plan.md 的实现差异说明

| 项 | plan.md | 本实现 | 原因 |
|---|---|---|---|
| go-redis 模块路径 | `github.com/go-redis/redis/v9` | `github.com/redis/go-redis/v9` | 旧路径已废弃，拉不到模块 |
| Redis 连接配置 | 硬编码在 main.go | 移入 config.yaml | 部署环境需要改地址，不能重新编译 |
| 管理接口鉴权 | 强制 token | 可选 token（留空不鉴权） | 用户决策：本期不考虑安全 |
| 管理保存持久化 | 只写 Redis | 双写：yaml 必写 + Redis 尽力 | 保证无 Redis 环境（本地联调）闭环完整、兜底文件与内存一致 |
| 新增接口 | 无 | `/healthz`、`/admin/test` | 探活与规则验证，成本极低 |
| 平滑退出 | 无（r.Run） | http.Server + SIGTERM 优雅退出 | systemd/守护重启不掉请求 |
| main.go 笔误 | `cfg.Listen` 引用未定义变量 | 修正 | 原样编译不过 |
